# Python UI (Feature-Parity Wizard)

This folder contains a Python UI for the Prompt Runner app.

The Python UI is designed to match the existing web wizard capabilities:

- Setup check (`/api/precheck`)
- Refresh login session (`/api/refresh-auth`)
- Dedicated profile manager step with create/edit/default/delete flows
- Manual request import into selected profiles
- Run modes: `simplechat-api`, `ui`, `api`
- File upload for input and optional network/selectors files
- JSONL profile/options and strict schema toggle
- Run context and artifact links
- JSONL preview/validation
- Run history refresh/clear
- Foundry export helper (`/api/export-foundry`)

## Prerequisites

1. Node.js 18+ (for backend runner)
2. Python 3.10+
3. Existing project dependencies installed in repo root:

```bash
npm install
npx playwright install chromium
```

## Start backend (required)

From repo root:

```bash
npm run wizard
```

Keep this terminal running.

## Start Python UI

From repo root:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r python-ui/requirements.txt
streamlit run python-ui/app.py
```

Or use the helper launcher:

```powershell
./python-ui/start-python-ui.ps1
```

## Use the app

1. In the sidebar, verify backend URL. Use `Auto-detect` if needed.
2. Open `Step 0: Setup` and run one-time setup checks.
3. Open `Step 1: Profiles` to manage/import templates.
4. Open `Step 2: Mode and files` and choose execution mode plus input files.
5. Open `Step 3: Config` to set query/reference/context columns and JSONL options.
6. Open `Step 4: Run` and execute batch.
7. Open `Step 5: History` to review prior runs.
8. Use artifact links to download Excel/JSONL outputs.

## Manual network template creation in Step 1

You can create the network template manually from a copied request, without running browser capture mode.

In **Step 0: Setup** and **Step 1: Profiles**:

1. Select the active profile in **Step 0: Setup**.
2. Open **Import copied request (updates template + model metadata)** in Step 1.
3. Paste one of the following:
	- A full `fetch(...)` call
	- A PowerShell `Invoke-WebRequest` snippet
	- A raw JSON request body
4. Click **Import request + update model**.
5. Run **Check setup readiness** in Step 0.

This writes to the selected profile template path (commonly `outputs/network-log-ui-full.json`).

### Sanitization behavior

- URL must target `/api/chat/stream`.
- Request body must parse as JSON object.
- Cookies and request headers are not persisted.
- Stateful conversation/message keys are removed before save.

### Troubleshooting

- If import returns endpoint-not-found, your backend is likely an older instance. Restart backend from repo root with:

```bash
npm run wizard
```

- If auto-detect picks the wrong backend, set backend URL manually in the sidebar.

## Notes

- The Python UI is a frontend to the existing Node backend API.
- Output files are generated by the same runner used by the original web UI.
- For first-time auth capture, use `Refresh login session` in Setup.
- Optional source-reference columns are supported in the input sheet:
	- `sources_json`
	- or flat fields like `source_title`, `source_url`, `ref_path`, `ref_pages`, `ref_scope`
	- numbered suffixes such as `source_title_1`, `source_url_1`, `ref_path_1` are also supported
- When source metadata is present, the runner asks for an exact `**Sources**` block and preserves `ref_path`, `pages`, and `scope` in output citations when those sources are cited.
